## Overview

Docker Compose is the recommended way to run Cossistant for development and small-scale production deployments. The included configuration sets up all required services with sensible defaults.

## Prerequisites

- Docker Engine 20.10+
- Docker Compose v2.0+
- Git (to clone the repository)
- 4GB+ RAM available
- 20GB+ disk space

## Quick Start

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/cossistant/cossistant.git
    cd cossistant
    ```
  </Step>

  <Step title="Copy environment file">
    ```bash
    cp .env.example .env
    ```
    
    Edit `.env` and configure at minimum:
    - Database credentials
    - `BETTER_AUTH_SECRET` (generate with `openssl rand -base64 32`)
    - `API_KEY_SECRET` (generate with `openssl rand -base64 32`)
    - `PUBLIC_APP_URL` (your domain or `http://localhost:3000`)
  </Step>

  <Step title="Start services">
    ```bash
    docker-compose up -d
    ```
    
    This starts PostgreSQL and Redis. For a complete setup including the API and workers, you'll need to build and run those containers separately (see below).
  </Step>

  <Step title="Run database migrations">
    ```bash
    bun install
    bun run apps/api/scripts/migrate.ts
    ```
  </Step>

  <Step title="Start the application">
    ```bash
    # Terminal 1: API Server
    bun run apps/api/src/index.ts
    
    # Terminal 2: Workers (optional)
    bun run apps/workers/src/index.ts
    ```
  </Step>
</Steps>

## Docker Compose Configuration

The included `docker-compose.yml` provides PostgreSQL and Redis:

```yaml docker-compose.yml
services:
  postgres:
    image: pgvector/pgvector:pg17
    restart: unless-stopped
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: cossistant
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
  redis_data:
```

## Building Custom Images

### API Server Image

The `Dockerfile.api` builds the API server:

```dockerfile Dockerfile.api
FROM node:20-slim

WORKDIR /app

# Install Bun
RUN npm install -g bun

# Copy package files
COPY package.json bun.lock turbo.json ./
COPY apps/api/package.json ./apps/api/
# ... (copies all package.json files)

# Install dependencies
RUN bun install

# Copy source files
COPY . .

# Build dependencies
RUN bunx turbo run build --filter=@cossistant/api^...

# Run with bun runtime
CMD ["bun", "run", "apps/api/src/index.ts"]
```

**Build the image:**

```bash
docker build -f Dockerfile.api -t cossistant-api:latest .
```

**Run the container:**

```bash
docker run -d \
  --name cossistant-api \
  --env-file .env \
  -e DATABASE_HOST=postgres \
  -e REDIS_URL=redis://redis:6379 \
  -p 8787:8787 \
  --network cossistant_default \
  cossistant-api:latest
```

### Workers Image

The `Dockerfile.workers` builds the background workers:

```dockerfile Dockerfile.workers
FROM node:20-slim

WORKDIR /app

# Install Bun
RUN npm install -g bun

# Copy package files
COPY package.json bun.lock turbo.json ./
COPY apps/workers/package.json ./apps/workers/
# ... (copies all package.json files)

# Install dependencies
RUN bun install

# Copy source files
COPY . .

# Build dependencies
RUN bunx turbo run build --filter=@cossistant/workers^...

# Run with bun runtime
CMD ["bun", "run", "apps/workers/src/index.ts"]
```

**Build the image:**

```bash
docker build -f Dockerfile.workers -t cossistant-workers:latest .
```

**Run the container:**

```bash
docker run -d \
  --name cossistant-workers \
  --env-file .env \
  -e DATABASE_HOST=postgres \
  -e REDIS_URL=redis://redis:6379 \
  --network cossistant_default \
  cossistant-workers:latest
```

## Complete Docker Compose Setup

For a full production-ready setup, create a custom `docker-compose.prod.yml`:

```yaml docker-compose.prod.yml
version: '3.8'

services:
  postgres:
    image: pgvector/pgvector:pg17
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DATABASE_USERNAME}
      POSTGRES_PASSWORD: ${DATABASE_PASSWORD}
      POSTGRES_DB: ${DATABASE_NAME}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DATABASE_USERNAME}"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - cossistant

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    volumes:
      - redis_data:/data
    command: redis-server --requirepass ${REDIS_PASSWORD}
    healthcheck:
      test: ["CMD", "redis-cli", "--pass", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - cossistant

  api:
    build:
      context: .
      dockerfile: Dockerfile.api
    restart: unless-stopped
    ports:
      - "8787:8787"
    env_file:
      - .env
    environment:
      - DATABASE_HOST=postgres
      - REDIS_URL=redis://redis:6379
      - NODE_ENV=production
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - cossistant

  workers:
    build:
      context: .
      dockerfile: Dockerfile.workers
    restart: unless-stopped
    env_file:
      - .env
    environment:
      - DATABASE_HOST=postgres
      - REDIS_URL=redis://redis:6379
      - NODE_ENV=production
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - cossistant

volumes:
  postgres_data:
  redis_data:

networks:
  cossistant:
    driver: bridge
```

**Start all services:**

```bash
docker-compose -f docker-compose.prod.yml up -d
```

## Health Checks

Monitor service health:

```bash
# Check all services
docker-compose ps

# Check specific service logs
docker-compose logs -f api
docker-compose logs -f workers
docker-compose logs -f postgres
docker-compose logs -f redis

# Check health status
docker inspect --format='{{.State.Health.Status}}' cossistant-postgres-1
docker inspect --format='{{.State.Health.Status}}' cossistant-redis-1
```

## Persistence and Backups

### Database Backups

Create automated PostgreSQL backups:

```bash
# Manual backup
docker-compose exec postgres pg_dump -U postgres cossistant > backup.sql

# Backup with compression
docker-compose exec postgres pg_dump -U postgres cossistant | gzip > backup_$(date +%Y%m%d).sql.gz

# Restore from backup
docker-compose exec -T postgres psql -U postgres cossistant < backup.sql
```

### Volume Management

```bash
# List volumes
docker volume ls

# Inspect volume
docker volume inspect cossistant_postgres_data

# Backup volume
docker run --rm \
  -v cossistant_postgres_data:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/postgres_backup.tar.gz -C /data .

# Restore volume
docker run --rm \
  -v cossistant_postgres_data:/data \
  -v $(pwd):/backup \
  alpine sh -c "cd /data && tar xzf /backup/postgres_backup.tar.gz"
```

## Updating

<Steps>
  <Step title="Pull latest changes">
    ```bash
    git pull origin main
    ```
  </Step>

  <Step title="Rebuild images">
    ```bash
    docker-compose -f docker-compose.prod.yml build --no-cache
    ```
  </Step>

  <Step title="Stop services">
    ```bash
    docker-compose -f docker-compose.prod.yml down
    ```
  </Step>

  <Step title="Run migrations">
    ```bash
    docker-compose -f docker-compose.prod.yml up -d postgres redis
    # Wait for databases to be ready
    bun run apps/api/scripts/migrate.ts
    ```
  </Step>

  <Step title="Start updated services">
    ```bash
    docker-compose -f docker-compose.prod.yml up -d
    ```
  </Step>
</Steps>

## Troubleshooting

### Service Won't Start

```bash
# Check logs for errors
docker-compose logs api

# Check if ports are already in use
lsof -i :8787
lsof -i :5432
lsof -i :6379

# Restart specific service
docker-compose restart api
```

### Database Connection Issues

```bash
# Test database connection
docker-compose exec postgres psql -U postgres -d cossistant -c "SELECT 1;"

# Check database environment variables
docker-compose exec api env | grep DATABASE

# Verify network connectivity
docker-compose exec api ping postgres
```

### Permission Issues

```bash
# Fix volume permissions
docker-compose down
sudo chown -R $(id -u):$(id -g) ./volumes
docker-compose up -d
```

### Out of Memory

```bash
# Check container resource usage
docker stats

# Increase Docker memory limit in Docker Desktop settings
# Or add memory limits to docker-compose.yml:
```

```yaml
services:
  api:
    deploy:
      resources:
        limits:
          memory: 2G
        reservations:
          memory: 1G
```

<Warning>
  **Production Note**: For production deployments, consider using managed database services (AWS RDS, DigitalOcean Managed Databases) instead of containerized databases for better reliability and automated backups.
</Warning>
