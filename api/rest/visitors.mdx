# Visitors API

Visitors represent anonymous browser sessions on your website. The API tracks device information, location data, and browsing behavior. Visitors can later be identified as contacts.

## Base Endpoint

```
PATCH  /v1/visitors/{id}
GET    /v1/visitors/{id}
PATCH  /v1/visitors/{id}/metadata
```

## Update Contact Metadata

`PATCH /v1/visitors/{id}/metadata`

Update metadata for the contact associated with this visitor. The visitor must be identified first using `/contacts/identify`.

### Authentication

<Snippet file="auth-public-key.mdx" />

### Path Parameters

<ParamField path="id" type="string" required>
  The visitor ID
</ParamField>

### Request Body

<ParamField body="metadata" type="object" required>
  Custom metadata to merge into the contact's metadata object. Supports nested objects.
  
  ```json
  {
    "metadata": {
      "plan": "enterprise",
      "company": "Acme Corp",
      "customFields": {
        "industry": "Technology",
        "employees": 50
      }
    }
  }
  ```
</ParamField>

### Response

Returns the updated visitor object (same as Get Visitor).

### Example

```bash
curl -X PATCH https://api.cossistant.com/v1/visitors/01JG000000000000000000000/metadata \
  -H "X-Public-Key: pk_test_abc123..." \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {
      "plan": "pro",
      "subscription_id": "sub_123",
      "lifetime_value": 5000
    }
  }'
```

## Automatic Data Enrichment

The API automatically enriches visitor data from request headers:

### IP Geolocation

When you don't provide location data, the API extracts it from:
- `CF-IPCity`, `X-Vercel-IP-City` → city
- `CF-IPCountry`, `X-Vercel-IP-Country` → country code
- `CF-IPRegion`, `X-Vercel-IP-Country-Region` → region
- `CF-IPLatitude`, `X-Vercel-IP-Latitude` → latitude
- `CF-IPLongitude`, `X-Vercel-IP-Longitude` → longitude
- `X-Vercel-IP-Timezone` → timezone

### IP Address Detection

Detected from headers in priority order:
1. `CF-Connecting-IP` (Cloudflare)
2. `X-Real-IP`
3. `X-Forwarded-For` (first IP)
4. `X-Client-IP`
5. Other standard headers

### Language Detection

Extracted from `Accept-Language` header if not provided.

### Country Name Resolution

If you provide a `countryCode`, the API automatically resolves the country name using the visitor's preferred language.

## Attribution Tracking

### First-Touch Attribution

Attribution data is stored on **first visit only**. Subsequent updates to the visitor will not overwrite existing attribution data.

This ensures you always know how a visitor originally found your site.

### Attribution Fields

<AccordionGroup>
  <Accordion title="UTM Parameters">
    - `source`: `utm_source` query parameter
    - `medium`: `utm_medium` query parameter
    - `campaign`: `utm_campaign` query parameter
    - `term`: `utm_term` query parameter
    - `content`: `utm_content` query parameter
  </Accordion>
  
  <Accordion title="Referrer & Landing Page">
    - `referrer`: Full URL of the referring page
    - `landingPage`: First page visited on your site
  </Accordion>
</AccordionGroup>

### Example Attribution Flow

```javascript
// Visitor arrives from Google Ads
// URL: https://example.com/?utm_source=google&utm_medium=cpc&utm_campaign=spring_sale

await client.updateVisitor('01JG000000000000000000000', {
  attribution: {
    source: 'google',
    medium: 'cpc',
    campaign: 'spring_sale',
    referrer: 'https://www.google.com/ads',
    landingPage: 'https://example.com/'
  }
});

// Later, visitor navigates to another page
// Attribution is preserved, not overwritten
await client.updateVisitor('01JG000000000000000000000', {
  currentPage: {
    url: 'https://example.com/products',
    title: 'Products'
  }
  // Attribution remains unchanged
});
```

## Page View Tracking

When you update `currentPage`, a page view event is automatically tracked in analytics.

```javascript
await client.updateVisitor(visitorId, {
  currentPage: {
    url: window.location.href,
    title: document.title,
    path: window.location.pathname
  }
});

// Automatically creates a page_view event
```

## Best Practices

<AccordionGroup>
  <Accordion title="Update on page navigation">
    Call this endpoint whenever the visitor navigates to track their journey:
    
    ```javascript
    // On initial load and every route change
    router.afterEach((to) => {
      updateVisitor(visitorId, {
        currentPage: {
          url: window.location.href,
          title: document.title,
          path: to.path
        }
      });
    });
    ```
  </Accordion>
  
  <Accordion title="Capture attribution early">
    Extract and store UTM parameters on the first page load:
    
    ```javascript
    const params = new URLSearchParams(window.location.search);
    const attribution = {
      source: params.get('utm_source'),
      medium: params.get('utm_medium'),
      campaign: params.get('utm_campaign'),
      term: params.get('utm_term'),
      content: params.get('utm_content'),
      referrer: document.referrer,
      landingPage: window.location.href
    };
    ```
  </Accordion>
  
  <Accordion title="Batch location data">
    Include as much location/device data as possible in a single request to reduce API calls.
  </Accordion>
  
  <Accordion title="Use metadata for custom properties">
    Store application-specific data in contact metadata rather than trying to add custom fields to the visitor object.
  </Accordion>
</AccordionGroup>
